# Air780EHV 模组端（无手机转发短信）

用一块 **合宙 Air780EHV** 4G 模组代替安卓手机做转发端：模组里插一张卡，收到短信就
**在模组上加密**（AES-256-GCM，和安卓端 / 网页端同一套密钥），HTTPS 上报到同一个 Cloudflare Worker。

```
[Air780EHV + SIM: 本固件] --HTTPS + 自己的设备密钥--> [Cloudflare Worker + D1] --浏览器--> [你]
```

为什么要它：一块核心板几十块钱、不到火柴盒大、直接 USB 供电就能长期挂机，不占手机、
不怕被系统「省电」杀后台，也没有安卓那种「强行停止后收不到广播」的坑。

**刷一次，永远不用再刷，也不用配置**：模组第一次开机自己生成一对设备 id / 密钥，向 Worker
**自注册**，在网页设备条上以「待信任」出现；你点一下 **信任** 它就开始工作。之后的重启、改域名、
更新脚本全在网页上点按钮，模组下一次轮询时取走执行 —— 放到再远的地方也不用拿回来插 USB。

> 先读 **[worker/README.md](../worker/README.md)** 把 Worker 部署好、拿到密钥。本文只讲模组这一端。
> 上报 / 收发的协议细节和安卓端完全一致，本目录的代码就是按安卓字节格式一比一移植的。

## 0. 给卖家的刷机包

```bash
cp luatos/config.lua.example luatos/config.lua   # 填上 SMS_KEY（cat worker/.sms_key）
bash luatos/pack.sh                              # → luatos/dist/smsgw-<版本>.zip + 给卖家的话
```

zip 里 **4 个文件**：

| 文件 | 说明 |
|---|---|
| `main.lua` | 启动脚本：计数、看门狗、配置、设备身份、加载 `gw.lua`（或它的 OTA 副本）、网页命令、救援模式。只刷这一次，以后不会被远程更新。 |
| `gw.lua` | 转发逻辑：注册、轮询、上报、发短信、ack。可网页 OTA。 |
| `gcm.lua` | 加密。可网页 OTA。 |
| `config.lua` | **`SMS_KEY` 必填**；`BASES` / `TOPIC` / `NAME` / `POLL_MS` / `CA_PEM` / `OWNER` 可选（默认值写死在 `main.lua`）。 |

底层固件 `LuatOS-SoC_V2050_Air780EHV_108.soc` 你自己从合宙官网下（§2），**不放进 zip**。
`pack.sh` 会拒绝空的 / 占位的 / 全 0 的 `SMS_KEY`。**zip 里含密钥**，只发给帮你刷机的人；`config.lua` 和
`dist/` 都在根 `.gitignore` 里。

给卖家的话（`pack.sh` 也会打印）：

> 麻烦用 Luatools 刷一下：新建项目 → 底层选 `LuatOS-SoC_V2050_Air780EHV_108.soc`（我自己提供）→
> 添加 zip 里的 4 个脚本（`main.lua`、`gw.lua`、`gcm.lua`、`config.lua`）→ 勾选「添加默认lib」→
> 点「下载底层和脚本」→ 下载完在日志里看到 `smsgw` 字样即可。刷完插卡通电即可，不用配置。

## 1. 买什么

| 东西 | 说明 |
|---|---|
| **Air780EHV 核心板** ×N | N = 你要挂几张卡。合宙官方核心板自带板载天线，**不用另买天线**；USB 口直接供电 + 下载。 |
| **一张已开通 VoLTE 的电信卡** | Cat.1 模组只上 4G，电信卡的短信走 IMS（SMS over IMS），**卡必须开通 VoLTE** 短信才进得来（合宙原话：电信卡只有开通 VoLTE 才能用短信；移动/联通卡不开也能收）。老电信卡默认常常没开，打 10000 或电信 APP 开一下。别用电信物联网卡，很多不带短信。 |
| USB-A 数据线 | 下载固件、供电。挂机时插充电头即可。 |

> 一块模组配一张卡。要挂多张卡就买多块，刷同一个包即可：每块**自动**分到独立的设备 id，
> 网页上各显示一张卡、各自信任，互不干扰（§8）。

## 2. 固件（选 108）

刷 **`LuatOS-SoC_V2050_Air780EHV_108.soc`**。这个变体（108）同时带齐了本项目要的三样：

- **`cc` 电话模块** —— 未接来电转发要用它监听 `CC_IND`；
- **电信短信 / VoLTE 短信**接收；
- **64 位整数** Lua —— GHASH 更快（代码在 32 位上也正确，见 `gcm.lua` 注释，但 64 位更省心）。

**`8` 也行**（功能齐、只是 32 位）。**别刷 `20` / `120`** —— 那两个变体**砍掉了短信**，
刷了就一条都收不到。另外只有 `{1,2,8,13,16}` 系列带 `cc`，其它变体**没有来电监听**，
未接来电转发会失效（短信仍正常）。

固件在合宙资料中心的 [Air780EHV 固件版本页](https://docs.openluat.com/air780ehv/luatos/firmware/version/)
下载（V2050 的目录：`https://cdn18.luatos.com/files/Air780EHV/LuatOS_Air780EHV/LuatOS-SoC_V2050_Air780EHV/`），
拿 `_108.soc` 那个。**别用 V2024 之前的版本** —— 那之前 LuatOS 的 AES-GCM
连 IV 都不生效（本项目绕开了它，但没必要踩老固件的坑）。

### Luatools 步骤（自己刷时）

1. 装 **Luatools**（合宙官方下载/烧录工具，Windows）。
2. USB 连上模组，Luatools 会自动认端口。
3. **第一次**：选「下载底层和脚本」，底层选刚下的 `LuatOS-SoC_V2050_Air780EHV_108.soc`，
   脚本添加 `main.lua` / `gw.lua` / `gcm.lua` / `config.lua`，勾选「添加默认lib」，下载。
4. 之后**不需要再连 USB**：改 `gw.lua` / `gcm.lua` 用网页「更新脚本」（§4）。
   真要用线刷也只需「下载脚本」，秒传。

## 3. 首次开机：网页上出现「待信任」→ 点信任

插卡通电。模组联网后：

1. 生成 **`dev_id`**（16 位十六进制）和 **`dev_secret`**（32 位十六进制），存进 fskv，以后不变；
2. **`POST /api/register`**：把自述信息（名字、SIM 运营商、固件、脚本版本、IMEI / ICCID / IMSI、
   OTA 状态、启动计数）用 `SMS_KEY` 加密后带上，Bearer 就是它自己的 `dev_secret`；
3. 网页顶部设备条出现一张**琥珀色高亮、标着「待信任」**的卡片，IMEI / ICCID 末几位能对上机身；
4. 你点 **信任**。模组每 30 秒轮询 `/api/poll`，下一次就看到 `trusted`，开始上报、领发送任务。

**信任之前**：收到的短信 / 来电会**留在模组队列里**（最多 50 条，满了丢最旧的），点信任后一起上报；
轮询只会回 `{"status":"pending"}`。**拉黑**同理（上报返回 403、模组把消息留在队列里等）。
彻底移除点 ✕（它再上报会重新变成待信任）。

模组每 30 分钟、以及每次看到信任状态变化时会**重新注册**一次，卡片上的「最近发送」/ OTA 状态 / 启动计数
就是这么刷新的。服务器只存 `sha256(dev_secret)`；手机端的 `SEND_TOKEN` 从不出现在模组上。

## 4. 网页操作（重启 / 改域名 / 更新脚本）

已信任的模组卡片下方有三个按钮，命令进 D1 的 `cmds` 表，模组**下一次轮询**取走执行，
执行结果（`done` / `failed` + 模组回报的原因）显示在卡片下。每台一次只排一条。

| 按钮 | 模组做什么 |
|---|---|
| **重启** | 先 ack `rebooting`，5 秒后重启（主动重启，不计入失败启动）。 |
| **改域名…** | 输入 `https://a,https://b`（最多 5 个，只收 `https://`）。浏览器用你本地保存的 `SMS_KEY` 对「`bases` + 换行 + 规范化后的地址串」算 **HMAC-SHA256**，签名随命令下发；模组用同一把钥匙对**收到的原串**重算，不一致就拒绝（ack `hmac`，什么都不改）。校验通过才存进 fskv `bases`，ack，5 秒后重启。用于域名被封 / 到期时搬家。没填密钥时按钮会拒绝操作。**新域名是「试用」的，见下。** |
| **更新脚本…** | 选本地的 `gw.lua` 或 `gcm.lua`（文件名决定替换哪个）。浏览器把文件传到 Worker（`/api/ota/put`），并用你本地保存的 `SMS_KEY` 对「`gw` + 换行 + 文件内容」算 **HMAC-SHA256**，签名随命令下发。 |

模组收到 `ota` 命令后：

1. 从 Worker 下载（`GET /api/ota/get`，≤ 200 KB，60 秒超时）；
2. 用 **`SMS_KEY`** 对「文件名 + 换行 + 内容」重算 HMAC，和命令里的比对 —— **服务器从来没有密钥**，
   Worker 被攻破也推不了代码；文件名参与签名，给 `gw` 签的文件装不进 `gcm`；
3. `load()` 编译一遍，语法错就拒绝；
4. 写到 `/ota_gw.lua`（`/ota_gcm.lua`），**回读核对**字节一致，ack `<字节数>`，10 秒后重启。

任何一步失败 ack `failed` + 原因（`http 404` / `size` / `hmac` / `compile` / `write` / `fskv`），什么都不改。
同一条命令因 ack 丢失被重发时，模组只重发上次的结果（fskv `last_cmd`），**绝不重跑**。

**保证**：刷进去的脚本永远不动，OTA 只写 `/ota_*.lua`；坏了自动回退，回退也坏了进救援模式（仍然连网页）：

- `main.lua` 每次启动给 `boot_fail` 加一。**活满 5 分钟、且 Worker 至少回过一次轮询**才清零 ——
  「起来了但一直连不上服务器」的 OTA 脚本不算健康。
- 装了 OTA 副本却 **15 分钟**没有任何一次轮询得到回应：算一次失败启动，重启。**连续 3 次**没活过：
  如果有 `/ota_*.lua`，**删掉它们**、清零、用刷进去的脚本继续跑（卡片上 `ota -`）；
  如果没有 OTA 副本 —— 说明刷进去的脚本本身跑不起来 —— 进**救援模式**（下）。
- 刷进去的脚本、没有 OTA 副本、只是断网：`main.lua` **不会**因此重启（断网不该让好设备反复重启）。
  `gw.lua` 自己连续 20 次轮询失败（约 10 分钟）会重启一次自救 —— 那是**主动重启**，**清零** `boot_fail`，
  所以一次长时间断网不会把好模组一路推进救援模式（救援模式里短信既不转发也不排队，会真的丢）。
  但**装着 OTA 副本时不清零**：一份起得来却永远连不上 Worker 的 OTA 脚本，照样 3 次之后被回退。
- **救援模式**：不加载 `gw.lua`、不上报、不转发短信；仍然**注册一次**（卡片上能看到 `boot=3`）、每 60 秒
  轮询 `/api/poll`，**照常执行网页的重启 / 改域名 / 更新脚本** —— 在网页上推一份好的 `gw.lua` 就能救回来。
  5 分钟后（且轮询有回应）自动再试一次正常启动；完全没网络则 15 分钟后再试。
  万一 flash 已经写不动也擦不掉（计数清不了），它**不重启**、留在救援模式里继续轮询（还能被网页救），
  而不是每 5 分钟空转重启一次。
- 看门狗在 `main.lua` 里、加载任何 OTA 脚本**之前**就启动（9 秒不喂就复位）：死循环的脚本会被复位、
  计一次失败、3 次后回退。
- 启动时编译不过 / 不返回模块的 OTA 副本（比如写到一半断电）直接删掉，卡片和 `#status` 里的 `ota` 只反映真正在用的副本。
- `main.lua` **不能**被 OTA（它就是做这件事的那一层），所以它每个分支都 `pcall`，由 `test/test_main.lua` 逐条覆盖。

### 改域名的「试用期」

改域名是整套里唯一一个**能把模组送到再也够不着的地方**的操作 —— 填错一个字母、或者填了个当时能通后来挂掉的域名，模组就再也连不上服务器，而能救它的那条命令恰恰要走这条断掉的链路。所以新域名先当「试用」：

- 模组**第一次成功轮询**（返回的必须是合法的状态 JSON，不是随便一个 200 —— 停放页/门户页也会回 200）才把它标记为已确认（fskv `bases_ok`）。
- 一直没确认的域名会被**自动丢弃**，退回 `main.lua` 里写死的内置域名：新域名在**第 1、2 次开机**联系不上，**第 3 次开机一上来就直接丢弃**（还没轮询就退回内置）。配合 `gw.lua` 连续 20 次轮询失败自重启，实际大约 **20–30 分钟**自己就回来了。前提是这期间**有数据服务**：如果恰好在这个窗口里赶上一次约半小时的**断网**，一个还没确认、其实没问题的新域名也会被这几次重启耗掉试用次数、退回内置（模组分不清「域名死了」和「没信号」）。
- **已确认的域名永不回滚** —— 正经搬完家之后，新域名哪天抽风断网，模组只会重试，绝不会莫名其妙跑回旧域名。代价是**已确认的域名如果真的死了，没有自动恢复**：只能靠 `#url`（需要 OWNER，而 OWNER 默认不填）或重刷。
- `#url reset`（需要 OWNER）或者再下一条「改域名」都会清掉覆盖和两个标记（网页轮询下发和 OWNER 短信两条路都一样）。

所以填错了不用慌。**但内置的那两个域名要是真过期了，那就只能重刷** —— `main.lua` 不能远程更新，写死的默认值也就改不了。记得开域名自动续费。

## 5. 可选的 OWNER 短信指令

默认**关闭**：`config.lua` 不填 `OWNER` 时，所有短信（包括以 `#` 开头的）一律当普通消息加密转发。
填了 `OWNER = "+86…"`，从这个号码（比较末 11 位，带不带 `+86` 都行）发来的、以 `#` 开头的短信被当作指令
**执行且不转发**；别人发的 `#…` 仍然转发给你。

| 指令 | 作用 |
|---|---|
| `#status` | 回一条：`2.0.0 csq=20 net=1 ip=10.x.x.x q=0 gcm=ok fw=V2050 trust=trusted ota=- boot=0`（信号 / 网络 / IP / 排队条数 / 加密自检 / 固件 / **信任状态** / OTA 副本 / 启动计数）。救援模式或 `gw.lua` 没起来时由 `main.lua` 回 `RESCUE boot_fail=… ota=… fw=… ver=… dev=…`。 |
| `#reboot` | 重启（主动重启，清零计数）。 |
| `#url https://a,https://b` | 等价于网页「改域名」：校验、存 fskv、回 `url ok rebooting`、5 秒后重启。 |
| `#url reset` | 清掉上面的覆盖，回到 `config.lua` / 默认域名，重启。 |
| `#ota gw <hmac>` / `#ota gcm <hmac>` | 等价于网页「更新脚本」：文件仍然从 Worker 下载（先在网页上传，或 `curl /api/ota/put`），签名用 `bash luatos/test/ota-sign.sh gw` 算。回 `ota ok gw <字节数> rebooting` 或 `ota fail: <原因>`。 |
| `#ota clear` | 删掉 OTA 副本，回到刷进去的脚本，重启。**永远由 `main.lua` 直接处理**，一个跑起来却不理短信的 OTA 脚本也拦不住它。 |

**安全边界**：主人身份**只靠短信的发送号码**，没有别的口令。能伪造 OWNER 号码的人可以让模组重启、
`#ota clear`，或者用 `#url` **把模组永久指到别的域名**（不是单纯的拒绝服务：改完之后模组只连新域名，
网页上「拉黑 + 忘记」都够不着它，只能再发一条 `#url reset` 或者拆下来重刷）。他看不到任何短信内容
——每个请求只带模组自己的 `dev_secret`，不带 `SMS_KEY`，回复也发到**真正的**主人手机上；装脚本同样
需要 `SMS_KEY` 签名，他没有。不放心就别填 `OWNER` —— 网页按钮能做的和短信一样多。

注意 `#url` 是**唯一不需要签名**的改域名入口：它已经用 OWNER 号码把门守住了，而且正是网页够不着时
（域名填错了、Worker 挂了、手边没有能签名的浏览器）的远程退路 —— 所以网络上来的 `bases` 一律要签名
（走 `_G.gw_cmd.run`），只有短信的 `#url` 走不验签的 `_G.gw_cmd.url`。填不填 `OWNER` 就是在
「多一个凭号码认人的入口」和「没有远程退路、只能拆下来重刷」之间选。

## 6. TLS

默认 **不校验服务器证书**（`CA_PEM = nil`）。这是有意的权衡，但要清楚它的代价。

**拿不到的**：短信正文端到端加密，中间人**看不到任何内容**；`SMS_KEY` 只待在 `config.lua` 里、从不上网，
所以他**推不了代码**（OTA 必须带 `SMS_KEY` 签名，与证书无关），也**带不走模组** —— `bases`（改域名）
是唯一能让模组永久改投别人服务器的命令，它和 OTA 一样**必须带 `SMS_KEY` 签名**（MAC 覆盖
「`bases` + 换行 + 地址串」，模组按收到的原串重算）。密钥只在 `config.lua` 和你浏览器的 localStorage
里，**服务器从来没有**，所以中间人伪造不出来，一个**被攻破的 Worker** 同样伪造不出来；模组收到没签名
或签名不对的 `bases` 就 ack `hmac`，什么都不改。

**能做到的**：他能**冒充 Worker 回话**，于是能**拒绝服务**（丢包、一直回 `pending`、让短信堆在模组队列里），
也能在某次请求里**偷走 `dev_secret`**（模组的身份凭据，可以拿去冒充模组上报垃圾）。两样都是可收回的：
停手就恢复；凭据泄漏在网页上「拉黑 + 忘记」即作废，模组下次自己重新注册。
**不会**再出现「模组被永久带走、拉黑和忘记都够不着」那一类不可恢复的后果。
即便如此，域名还是要用你自己控制、不会被别人接管的；在意这一条就按下面开证书校验。

LuatOS 的 mbedtls 校验 Cloudflare 轮换的证书链本身就不稳（GTS ⇄ Let's Encrypt 会静默换发），
默认关掉是为了可用性。

想开校验：把 Cloudflare 当前签发链的 CA（如 GTS WE1 + GTS Root R4）拼成一个多证书 PEM
字符串填进 `config.lua` 的 `CA_PEM`，代码会把它作为第 6 个参数传给 `http.request` 并转成 VERIFY_REQUIRED。
**注意证书轮换可能让固定 CA 某天突然握手失败** —— 要么两套根都塞进去，要么就用默认的不校验。

## 7. 两块以上模组

每块模组**首次开机自动**生成 16 位十六进制设备 id（存 fskv `dev_id`，之后不变），用作 `?dev=`
和加密 JSON 里的 `d`。所以：

- 网页设备列表里**每块模组各占一行**，各自信任，心跳独立，一块掉线不会掩盖另一块。
- **定向发送**：在网页的发短信面板选具体的卡（SIM picker），那条 outbox 行只会被对应模组认领，
  不会被另一块抢走从错误的卡发出去。不指定卡（`dev` 为空）则任意在线模组都可能认领 ——
  单模组场景无所谓，多模组建议都定向。
- 刷同一个包即可；想在网页上分清楚，`config.lua` 的 `NAME` 各起一个名字，或者看卡片上的 IMEI 末几位。

## 8. 限制与额度

- **单条明文 ≤ 3000 字节**：超长短信在 UTF-8 边界截断并加 `…[截断]` 标记（和安卓端同一处字节）。
- **outbox 认领窗口 5 分钟**：网页排的待发短信，模组认领后若 5 分钟内没回 ack，服务器会重新派发；
  模组用「已处理环」（最近 40 条）去重，**重发的行只会被重新 ack、绝不重复发**（详见 `gw.lua`）。
- **每 30 秒轮询一次** ≈ **2880 次请求/天/模组**，加上上报和每 30 分钟一次注册，远在免费额度（10 万/天）内。
- 加密自检失败时**不上传任何东西**（`gcm=FAIL`），只保 `#status` 可用，避免传出解不开的垃圾。
- **没有 `config.lua` / `SMS_KEY` 不合法**：什么都不做，每 60 秒打一条 `config.lua missing/invalid` 日志（USB 串口能看到）。
- **待信任的设备最多堆 20 个**，再多注册返回 429（Worker 端限制）。
- **改域名有试用期**：新域名没成功轮询过就连续 3 次开机联系不上，自动退回内置域名（见 §4）。

## 9. 排障

| 现象 | 多半是 |
|---|---|
| 通电很久网页上没出现「待信任」 | 卡没开 VoLTE / 没信号（有 OWNER 就发 `#status` 看 `net` / `ip`）；`config.lua` 没刷进去或 `SMS_KEY` 不合法（串口日志每分钟一条）；域名不对（`BASES`）。 |
| 出现了但一直「待信任」 | 你还没点信任。 |
| 网页显示「🔒 无法解密」 | `SMS_KEY` 和网页 / 模组不一致；或 `#status` 里 `gcm=FAIL`（加密自检没过，别的都别看，先解决这个）。 |
| 信任后短信没上来 | 看卡片是否在线（最近轮询）；上报 **404** = `TOPIC` 不对（`config.lua` / 默认值 ≠ `wrangler.toml` 的 `TOPIC`），这类被判为永久错误、直接丢弃。 |
| 命令一直「待执行」 | 模组没在轮询（离线）；或它在救援模式、每 60 秒才取一次。 |
| 命令 `failed hmac` | 浏览器里保存的密钥 ≠ 模组 `config.lua` 里的 `SMS_KEY`；或文件名和槽位对不上（给 `gw` 签的装到 `gcm`）。 |
| 命令 `failed http 404` | 脚本没上传成功（`/api/ota/put`），或 KV 里的槽位名和命令的不一致。 |
| 卡片上 `ota -` 但你明明推过 | 新脚本连续 3 次没活过（起不来，或 15 分钟连不上服务器），已被自动回退。修好再推一次。 |
| 改完域名后设备失联 | 填错了。等约 20–30 分钟：没确认过的域名试两次开机、第 3 次开机直接丢弃，退回内置域名（§4，前提是这期间有数据服务）。有 OWNER 的话发 `#url reset` 立刻恢复。 |
| 卡片上 `boot 3` | 救援模式：刷进去的 `gw.lua` 起不来。在网页上推一份好的 `gw.lua`，或 `#ota clear` / `#reboot`（需要 OWNER）；它自己也会每 5–15 分钟再试。 |
| 电信卡收不到短信 | **VoLTE（IMS）没开通**；或刷了不带短信的固件（确认是 `1/2/8/13` 系列，别用 `20/120`）。 |
| 来电不提醒（未接来电不转发） | IMS 未注册，用 AT 或日志看 `IMS_REG` 状态；或固件不带 `cc`（非 `{1,2,8,13,16}`）。 |
| 网页上一直「离线」 | 模组没成功轮询：看 `#status` 的 `net` / `ip`；连续 20 次轮询失败模组会自动重启自救。 |

## 10. 本地跑测试

模组端逻辑在 `test/fake_luatos.lua`（虚拟时间调度 + curl 实发 HTTP + `/ota_*` 文件沙盒）下用桌面 `lua`

```bash
cd /path/to/sms

# 语法检查
luac -p luatos/*.lua luatos/test/*.lua

# 加密向量 + Node 交叉校验（AES-256-GCM 逐字节对拍）
lua luatos/test/test_gcm.lua

# gw.lua 纯函数单测 + 经 main.lua 启动的运行时烟测：注册 → 待信任 → 信任 → 上报 / 发送 / ack、
# 403 保留队列、网页命令（重启 / 改域名 / 更新脚本、去重）、忘记后自动重新注册、OWNER 短信指令（274 条断言）
lua luatos/test/test_gw.lua

# main.lua 全生命周期：无 config.lua → 注册 / 信任 → 命令去重 → OTA + 看门狗 → 坏脚本回退 →
# 不联网的 OTA 脚本回退 / 断网的原厂脚本不进救援 → 救援模式（注册、轮询、网页 OTA 修复）

```

`e2e.sh` 会：在临时目录里生成一把随机测试密钥和一份 `config.lua`（**绝不写进仓库**），运行时才从
`wrangler.toml` / `.dev.vars` 读 TOPIC 和网页账号，从 `main.lua` 启动整个模组对本地 Worker 真发注册 / 轮询 /
上报 / ack，用 curl 扮演网页（登录、信任、拉黑、发命令、上传脚本 + `openssl` 签名），再用 Node 解密本地 D1
里的密文，逐字节断言注册信息、收件、未接来电、发送 + ack、重发去重、坏密文、错 topic 丢弃、断网不上报、
重启命令、OTA 安装并在重启后生效、错槽位签名被拒、改域名、拉黑 → 403 保留 → 再信任 → 补发 —— 每条打印 `✅`，
跑完自动清理它建的行和 KV。
